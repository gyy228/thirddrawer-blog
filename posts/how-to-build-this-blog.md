这个站的全部成本是零：没有服务器，没有数据库，没有月费。

下面是具体怎么做的，以及踩过的坑。如果你也想搭一个，可以照着走。

## 为什么不用服务器

一台最便宜的云服务器一年也要两三百，还要管续费、管备份、管证书过期。

而我需要的东西只有一个：**把几个 Markdown 文件变成网页**。这件事完全可以在构建时做完，不需要运行时的任何东西。

所以选了静态导出——构建时生成 HTML，之后就是几个文件躺在那里，谁访问都一样，快且不会挂。

## 技术栈

| 层 | 选型 | 为什么 |
|---|---|---|
| 框架 | Next.js（`output: "export"`） | 生态全，静态导出够用 |
| 样式 | Tailwind CSS | 写起来快，产物小 |
| 内容 | Markdown 文件 | 不锁死在某个后台里 |
| 托管 | GitHub Pages | 免费，且和代码同一个仓库 |
| 部署 | GitHub Actions | 推代码就自动发布 |
| 图片 | 直接放 `public/` | 省掉对象存储 |

## 三个必须注意的地方

### 1. 静态导出下，动态路由至少要生成一页

`/posts/[slug]` 这种路由，如果一篇文章都没有，构建会直接失败：

```
Error: Page "/posts/[slug]" returned an empty array from
"generateStaticParams()". With "output: export", at least one
route must be generated.
```

这不是 bug，是静态导出的硬限制——没有服务端，所有页面都得在构建时生成好。

解决办法有两种：至少留一篇文章，或者给个占位路由让它生成一页 404。

### 2. `sitemap` 和 `robots` 也要声明静态

```ts
export const dynamic = "force-static";
```

文档里没提，但不加就是构建失败。这两个本来每次构建只生成一次，声明成静态是合理的。

### 3. basePath 处处都要带

站点挂在 `用户名.github.io/仓库名/` 下，所有资源路径都要带这一层前缀，**漏一个就 404**。

```ts
const BASE_PATH = "/thirddrawer-blog";
```

我把它抽成了一个常量文件，因为散在三个地方各写一遍，早晚会改漏一个。

## 部署

推送到 `main` 就自动发布，配置在 `.github/workflows/deploy.yml`：

```yaml
on:
  push:
    branches: [main]
```

构建完产物上传，由 GitHub Pages 分发。整个流程大概一分钟。

## 内容怎么改

两条路：

**一、在网页里改。** 打开 `/console/`，粘一个 GitHub 访问令牌，然后就能增删改文章、说说、照片。

这是纯前端的——浏览器直接调 GitHub API 写仓库，没有中间服务器。令牌是 GitHub 在服务端校验的，所以确实只有自己能进。

**二、直接改文件。** `posts/*.md`，提交推送，一样会部署。

## 每日选刊怎么自动跑

这是唯一一个会「自己动」的部分，用 GitHub Actions 的定时任务：

```yaml
schedule:
  - cron: "0 0 * * *"   # UTC 0 点 = 北京时间 8 点
```

每天抓八个订阅源，把候选喂给模型挑五条，生成 JSON 提交回仓库。

**这里踩过三个坑，都是「工作流显示成功但什么都没做」：**

1. **时区** —— runner 是 UTC。北京时间 0 点到 8 点之间跑，算出来的「今天」是昨天，命中已有文件就静默跳过了。
2. **输出额度** —— 模型会先「思考」，`max_tokens` 同时限制思考和回答。给的额度被思考吃完，正式回答就是空的。
3. **参数没传进去** —— 用表达式拼命令行，拼出空串时命令依然合法，于是按默认模式跑。

共同点是**都返回成功**。所以现在的做法是：跑完必须检查产物本身存不存在，不存在就 `exit 1`。

> 绿色的成功勾不等于做了事。这是我这个站被教的最深的一课。

## 要不要也搭一个

成本很低，前提是你能接受：

- 没有评论系统（除非自己接第三方的）
- 没有访问统计（除非自己接）
- 每次改内容都要一次提交（因为内容也在 git 里）

前两条我觉得无所谓，第三条反而挺舒服——**所有改动都有记录，改错了能翻回来**。
